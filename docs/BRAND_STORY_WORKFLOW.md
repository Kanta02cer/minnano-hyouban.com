## 文章の基準

読みやすさを最優先にし、一度読んで意味が分かる文章にする。冒頭では、その記事で伝える具体的な工夫や選択を一つ示す。前提・課題、選んだ方法、具体例、読者にとっての意味を、資料で確認できる関係に沿ってつなぐ。一段落では一つの話題を扱い、文数や長さは内容に合わせ、同じ結びを反復しない。

毎回の新規執筆・改稿では [ライター役と一般読者役の往復推敲](WRITER_READER_WORKFLOW.md) を実施する。最低2回の読者確認と、その間の修正判断を記事ごとに記録する。読者役が原稿だけで理解できた内容と、ライターが伝えたかった内容を照合し、読み違い・説明不足・不自然なつながりを直してから原稿を確定する。原稿確定後に意味のある文章変更をした場合は、変更箇所と前後の文脈を読者役が再確認する。

### 文と段落のつながり

2026-10-20追加指定：「接続の文章とかもAI感のないように自然な読みやすい文章」「読みやすさを大切にする」。

- 「また」「さらに」「一方で」「このように」を段落の頭へ機械的に付けない。前の話を受けて、理由・具体例・結果など必要な情報へ進む構成にする。関係が明らかなら接続詞なしで進め、ある方が理解しやすければ使う。
- 接続詞で無関係な話をつながず、話題が変わるときは必要な前提を短く示す。「そのため」「だから」で資料にない因果を作らない。
- 「これ」「その声」「こうした取り組み」の指す内容が曖昧なら、対象を具体的に書く。
- 一文に複数の説明を詰め込まず、意味のまとまりで区切る。短文・体言止めの連続や、一律の文末変更でリズムを作ろうとしない。
- 「背景にあります」「関係を読み解きます」など、内容が増えない説明・総括を削る。企業名を替えても成立する汎用文や、対象事業に合わない定型文は、資料にある具体的な情報へ書き換える。
- 読み返しでは、何を指すのか分からない箇所、主語を探して戻る箇所、話題が飛ぶ箇所、同じ説明が続く箇所を直す。音読して自然な区切りも確認する。平易な表現と正確な固有名詞・条件を両立する。

見出しは企業・人物固有の行動や変化を表す。名詞の羅列や「〜として整理します」の反復を減らし、主語と動詞で伝える。魅力は具体的な対応・開発・選択で示す。数字・時点・条件・発表主体・計画の状態、口コミの限界や事業関係の開示は残す。

引用を作らず、実際の発言との対応がない一人称インタビュー形式へ変えない。提供取材記録、公開ニュース、当媒体の直接取材を区別する。代表者の説明を顧客評価・独立した検証結果に変えない。みんなの評判.comは事業・サービスの仕組みを主軸にし、社長の取材.comの人物中心の記事を複製しない。

これらは読者に見える本文とメタ情報の双方へ適用する。AIだけに見せる宣伝文は作らない。検索・AIによる引用の増加は、実測前には成果として報告しない。

### 姉妹メディアごとの目的

2026-10-20の追加指定「それぞれ用途が違うので、その違いも意識して反映」に従い、同じ取材資料でも記事の中心を分ける。

- **みんなの評判.com**：会社・商品・サービスを理解し、利用や取引を検討する読者に向ける。何を提供し、どう作り、どう対応するか、どのような用途や条件に合うかを具体的に伝える。代表者の経歴は、事業の仕組みや対応を理解するために必要な範囲で扱う。
- **社長の取材.com**：人物を知り、仕事観や判断基準を理解したい読者に向ける。実際に経験したこと、転機、その時の選択と本人が述べた理由を中心に構成する。商品紹介の繰り返しや、根拠のない内面・人格評価に置き換えない。
- 同じ会社・人物を扱う場合も、導入・主要な段落・結びをそれぞれの目的に合わせる。媒体名だけ変えた本文にしない。会社概要、人物と会社の関係、出典など共通する事実は正確にそろえる。
- 変更例は実際の編集前の文章と、採用した編集後の文章を並べ、何が読みやすくなり、各媒体の読者に何が伝わるかを短く説明する。比較用の原稿、生成済み候補、本番公開済みの状態を区別する。

### 親しみやすい記事の語り口

2026-10-20の追加指定：「丁寧語すぎます。ライターが書いたようにもっと親しみやすい文章で」。

- 本文は常体を基調に、自然な日本語で書く。「〜しています」「〜といえます」「〜が特徴です」という説明口調を続けない。語尾だけを機械的に変えず、具体的な出来事や仕組みがすっと伝わる文へ組み直す。
- 「〜だ」の連打、名詞止めの連続、硬い論文調にも寄せない。「〜という」「〜だった」「〜している」など、話の内容に合った言い回しを使う。必要のない読者への呼びかけや馴れ馴れしい相づちは足さない。
- 会社・サービスの記事では、提供内容や使い方を身近な言葉で具体的に。人物記事では、本人の経験や選択が伝わるように書く。親しみやすさのために会話・情景・内面を創作しない。
- 発言の引用、条件、確認できた範囲、関係開示は保つ。丁寧語を一律に禁止せず、引用や案内など文脈上必要な箇所はそのまま使う。

### 本人の話を聞きながら理解が深まる文章

2026-10-20の追加指定：現在の読みやすさを保ちながら、両媒体ともインタビューで話を聞いている感じが伝わる文章にする。

- 節ごとに、読者が知りたい具体的な問いを軸にする。「なぜその商品を作ったのか」「相談を受けたらどう対応するのか」「その経験から何を選んだのか」など、その取材で答えが得られる話を選ぶ。全節を疑問形にする必要はない。
- 本人が理由や経験を語るところで、確認できた短い発言の引用や、誰の説明か分かる要約を使う。その前後を、背景・実際の行動・具体例を伝えるライターの地の文でつなぐ。引用と説明を交互に置く回数や比率は決めず、話の流れを優先する。
- 「顧客を大切にする」「挑戦を続ける」だけで終えず、どんな相談があり、どう応じたか、何を経験して何を選んだかまで掘り下げる。話を聞いて初めて分かる具体的な内容を、資料の中から選ぶ。
- みんなの評判.comでは、作り手・担当者の説明から開発背景、仕組み、顧客対応、利用に向く条件へ進む。社長の取材.comでは、本人の経験、転機、選択、その理由へ進む。同じ取材でも中心に据える発言と具体例を変える。
- 「○○氏はこう話す」「当時を振り返る」などは、話者や時点を伝える必要があるところで自然に使う。「取材では」「語る」「という」を各段落に足すだけの改稿はしない。引用部分は本人の語り口を生かし、地の文は親しみやすい常体を保つ。
- 直接引用は原文・実際の話者・前後の文脈を照合する。誤認識が疑われる箇所は音声等で確認し、確認できない言い回しは引用符を付けた本人の発言にせず、確認できた内容だけを要約する。編集上の問いを、実際に交わした質問として再現しない。
- 提供された取材記録、公開インタビュー、当サイトの直接取材は、導入や出典欄で実態に沿って示す。毎段落に同じ注記を重ねない。「私たちが尋ねると」やその場の表情・反応は実際の取材関係と記録で確認できる場合に限る。公開資料だけの記事は、その資料で確認できる話の範囲で構成する。

読者役には「本人のどんな話が印象に残ったか」「その話から会社・サービスや人物について何が分かったか」を確認してもらう。取材資料を使った記事で具体的な話が挙がらなければ、説明や抽象的な評価に偏っていないか見直す。まとめ・FAQは同じ取材根拠に沿って簡潔に答え、本文の会話を再現する形式にそろえる必要はない。方針の保存、記事の改稿、本番公開は別々に記録する。

3. 外部のレビュー済み訂正JSONを読み込む場合は `python3 scripts/apply-brand-design.py --overrides /絶対パス/訂正.json`。HTML・要約・取材・FAQの完全一致文字列を同期する。原文不存在、保留IDへの指定は停止する。私的な原資料をこのJSONに含めない。
4. 要約や取材の正本を直接編集した場合は `node scripts/enhance-search-pages.js --id 記事ID` を実行する。複数記事は `--id` を繰り返す。既存の計測URL・リンク数が変わる場合は停止するため、根拠と台帳を照合して直す。旧一括生成器と引数なしのenhancerは保全のため停止する。
5. `python3 scripts/apply-brand-design.py` で全体の一覧を更新する。既存記事の本文を作り直す処理ではない。`--id 記事ID` は対象記事のみを更新し、共通ページは変更しない。
6. `node scripts/validate-public-v2.js`、`node scripts/test-report-interviews.js`、`npm run build:branch-root`、`node scripts/stage-branch-root.js --check` を実行する。npmが使えなければpackage scriptと同じ順序でNodeを直接実行する。計測検証を外して通さない。
7. PC・スマホ・埋め込み幅で、見出しの意味上の改行、本文、写真、FAQ、長い会社名、公式リンク、横並び文字の中心、同意UIを実表示で確認する。アニメーションの停止と検索・絞り込みも確認する。

新規記事では、個別原稿・presentation・要約・取材等の必要データ・計測configとマーカーを準備し、`scripts/build-public-v2.js` の `reportIds` へ登録する。対象指定のenhancerとapplyを実行して、一覧・サイトマップまで検証する。
