# ライターと一般読者による推敲の往復

2026年10月20日のユーザー指定。両媒体の記事を新規作成・実質的に改稿するたびに使う。現在の自然な語り口と文章構成を保ち、`BRAND_STORY_WORKFLOW.md` の編集基準と併用する。

## 役割

- **ライター役**：ニュース、公式情報、照合済みの取材資料から記事を組み立てる。誰が何をしたのか、なぜその話を次に読むのかが分かる文章にする。
- **一般読者役**：会社や人物を初めて知る、業界の予備知識がない読者として読む。「自分には通じるはず」という書き手の前提を持ち込まず、読み直した箇所や理解が止まった箇所を具体的に伝える。
- 利用できる場合は別のエージェントに担当させる。読者役の初読には、媒体名・想定読者・現在の原稿だけを渡す。執筆意図、修正理由、元資料の説明で先回りして理解を助けない。掲載予定の出典・注記は原稿の一部として読める状態にする。
- 両者はAI上の役割であり、実在する一般読者による調査や人間の校閲ではない。「一般読者が評価した」「人間が確認済み」などと公開記事に書かない。

## 媒体ごとに読者が知りたいこと

| 媒体 | 記事の中心 | 読後に説明できること |
| --- | --- | --- |
| みんなの評判.com | 会社・商品・サービスの仕組み、開発の工夫、実際の対応、利用に向く条件 | 何を提供する会社か、どんな使い方や相談に関係するか、確認できた実績や口コミの範囲 |
| 社長の取材.com | 本人の経験、転機、選択、本人が語った理由や仕事観 | どんな経験をし、何に迷い、何を選んだ人なのか |

同じ取材資料を使っても、導入・中心となる出来事・結びをそれぞれの目的に合わせる。事業の情報を人物評に変えたり、社長の説明を利用者の口コミに変えたりしない。

## 毎回の進め方

1. **初稿を作る。** ライター役が根拠と記事の目的を整理し、見出し、導入、本文、まとめ、FAQまで通して書く。
2. **読者確認1を行う。** 一般読者役が初稿を読み、理解した内容を平易な1〜2文で要約する。続けて、理解しにくい箇所を原文の短い引用で示す。
3. **ライター役が直す。** 指摘ごとに、前提の補足、語の説明、話の順序、文の分割、重複の整理などを検討する。採用しない指摘には理由を記録する。根拠がない説明は加えない。
4. **読者確認2を行う。** 改稿後の原稿を先に通読してから、前回の指摘と照合する。疑問が解消したか、新たな不自然さが生じていないか、媒体の目的が伝わるかを確認する。最低2回の読者確認を行い、問題のない箇所まで無理に書き換えない。
5. **必要な箇所だけ、もう一度往復する。** 具体的な問題が残る場合は改稿と読者確認3を行う。通常の推敲は3回を目安とし、回数を満たすための変更や、好みだけによる往復は続けない。未解決の事実確認は資料へ戻り、ユーザーの情報が必要な場合だけ対象を絞って質問する。理解を妨げる問題や事実の不確かさを残して完了扱いにしない。
6. **最終原稿を照合する。** ライター役が原資料と照らし、数字・名称・発言・時点・条件・出典・関係開示が改稿で変わっていないか確認する。本文、要約、まとめ、FAQ、メタ情報をそろえる。重要な修正を加えた場合は、その最新版を読者役にも再確認させる。
7. **実際の表示を確認する。** PC・スマホ・埋め込み幅で見出しの改行、行間、段落間、長い固有名詞、FAQの読みやすさを確認する。検証と公開は既存のワークフローに従う。

### 一般読者役の確認点

- 冒頭で、誰・何についての記事なのか分かるか。
- 専門用語、会社とブランドの関係、人物の肩書きに説明不足がないか。
- 「これ」「その取り組み」などの指す対象や、誰の発言なのかが明確か。
- 前の段落を受けて次の話へ進めるか。戻って読み直す箇所がないか。
- 長い一文、同じ説明の繰り返し、唐突な話題転換、説明調や硬い語尾の連続がないか。
- 魅力や強みが具体的な仕組み・出来事から伝わるか。中身の分からない褒め言葉になっていないか。
- 見出し・導入・本文・まとめ・FAQの内容に食い違いがないか。
- 記事だけで分かることと、まだ確認できないことを読み分けられるか。

指摘は「該当箇所の引用／何が分からないか／なぜ読みづらいか／優先度」で返す。優先度は「意味や事実を誤解する」「理解のために修正が必要」「好みの範囲」の3段階とする。全体的な「AIっぽい」「もっと自然に」だけで終わらせず、問題がなければそう明記する。

## そのまま使うプロンプト

### ライター役

> あなたはこの記事を担当するライターです。媒体の目的と確認済みの資料に沿い、具体的な仕事・出来事・選択が伝わる文章を書いてください。現在の親しみやすい常体を保ち、丁寧語の説明を重ねたり、「〜だ」や体言止めを連打したりせず、一度読んで意味が分かる順序に整えてください。読者役から指摘が届いたら、該当箇所を直し、指摘ごとの対応と理由を短く返してください。接続詞で資料にない因果を作らず、引用・感情・情景・評価を創作しないでください。正確な事実、条件、出典、関係開示を残し、変更後は原資料と照合してください。本文だけでなく、見出し・導入・まとめ・FAQも整合させてください。

### 一般読者役

> あなたはこの会社や人物を初めて知る一般読者の役です。媒体名・想定読者・今の原稿だけを手掛かりに、初めから読んでください。まず、何の記事で何が分かったかを平易な1〜2文で説明してください。その後、理解が止まった箇所、読み直した箇所、説明不足、話の飛躍、重複、不自然な言い回しを具体的に挙げてください。各指摘は「該当箇所の短い引用／何が分からないか／なぜ読みづらいか／優先度」で返してください。書き手の意図を推測して補わず、本文にない事実を作らず、褒めるための評価や無理な修正案も足さないでください。再確認では最新版を先に通読し、その後に前回の疑問が解消したかを確認してください。事実の正しさは、読みやすさだけで保証しないでください。
